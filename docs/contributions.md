# Shared feedback and package sources

ZIP import with a readable manifest posts a bounded JSON contribution to `/api/contributions`. It never uploads the ZIP or artwork and never fetches a provenance URL. User-authorized shared collection is separate from the local importer. Unreadable ZIPs or manifests do not submit. A readable manifest can contribute valid feedback even when its artwork fails validation. Valid feedback can submit even when source records are absent; eligible sources can submit without feedback. Standalone diagnostic file imports remain local.

The endpoint uses the CATALOG_CONTRIBUTIONS Durable Object binding and CONTRIBUTION_RATE_LIMITER. Deploying the included migration creates its storage. Same-origin JSON requests only, 64 KiB maximum, three attempts per requesting IP per minute, 1,000 unique contribution records at capacity. A SHA-256 fingerprint of the manifest is the submission ID. Reimporting the same manifest counts once. A newly generated pack has a new manifest and can report fresh link observations, even when its diagnostic counts match a prior run. The fingerprint does not expose the raw manifest. Records and source observations expire after 90 days, with a daily alarm deleting expired data. Public reads exclude expired entries even before cleanup. Workers never fetch contributed URLs.

Set `CONTRIBUTION_ADMIN_TOKEN` with `npx wrangler secret put CONTRIBUTION_ADMIN_TOKEN` to enable the protected `GET /api/contributions` export. Supply it in an Authorization Bearer header, never in a URL. Without that secret the export returns 403. There is no public feedback export. Exports downloaded by the maintainer need to be handled and deleted separately from server retention.

`GET /api/sources?catalogId=<existing catalog ID>` returns up to five recent source suggestions, with their last server receipt date and agent-reported observations. These are untrusted leads, not reviewed endorsements. The latest unavailable/wrong-package observation suppresses the URL. Known catalog identifiers avoid storing arbitrary user-entered blend names. Custom or unmatched blends need catalog curation before their sources can contribute.

The source extension is an array at each label's `extensions["tin-to-cellar:sources"]`, up to ten entries with exactly `url`, `status`, `package`, `variant`. The collection payload adds the matched `catalogId`. Values are specified in protocol revision 3. Stable HTTPS links must have no query, fragment, credential, explicit port, or local/IP host. No free-text analysis, source titles, attachments, original filenames, or image copies are collected. Original research remains in the local manifest. Older package-appearance source links become unverified leads.

Source lookups are included for exact catalog selections in project input. The AI must inspect matching suggestions first, research gaps, and report failed suggestions and eligible replacements. The general diagnostic feedback schema stays at 2.0.0. Protocol releases 1 and 2 remain immutable.

The privacy page describes this application behavior and Cloudflare processing. Public source links are intentionally reusable and may reveal information in their paths; technical filtering does not certify an arbitrary URL as anonymous. The agent instructions prohibit private or personal links. The system stores structured source observations, not free-text packaging analysis.
